ChristEye implementation and development guide

Engine 2.17 | Documentation 1.256 | November 12 2026

This release connects layered source contracts to executable semantic changes and bounded workflow construction. Use the one-expression path for a reviewed individual edit and the compiled path for a mixed behavior. Both retain the source, target, review and result. The examples use authored judgments and internal records.

CapabilityCurrent behavior
Source contracts93 contracts account for ten layers; five have executable expression rules and 88 retain inquiry gaps.
Semantic executionStructured transformations and controlled rendering prevent status and prose from contradicting each other.
Mixed expressionA finite serial graph can combine qualification, clarification, questions and later review in one retained transaction.
ConstructionA bounded planner generates new compositions from immutable primitives and declared goals.
DevelopmentA frozen evaluator can select a tested successor automatically and retain its predecessor for rollback.

Verification: 523 unit tests, 16 original invariant checks, 46 authored Astral checks, seven weighted coordination comparisons, 11 covenant checks, 16 expression checks and 21 layered construction checks. No live Gemma, Unity or TTS execution is claimed. The 12-case improvement demonstration measures completion of authored structured task bundles only.

Run the package

Extract christeye_machine_v2_17.zip and run commands from its root. Install the pinned requirements in an isolated Python environment. Output directories for demonstrations must be new.

python -m pip install -r requirements.txt

python expression_demo.py results/expression

python layered_behavior_demo.py results/layered

python -m unittest discover -p "tests*.py" -q

python tests_v2.py

python covenant_demo.py results/covenant

python weighted_coordination_demo.py results/weighted

python astral/run_scenarios.py --engine . --output results/astral

The layered example writes the source contracts, incumbent, candidate, construction search, frozen protocol, comparison, selected packet, execution receipt, retained state and development history. SQLite stores support restart checks. The candidate and comparison are versioned separately from the source corpus.

The root-relative engine_2_16_to_2_17.patch is an alternative for an unchanged 2.16 checkout. Apply with git am; the full engine ZIP is the complete runnable deliverable. The release commitment is independent/FREEZE_v2_17.json. It is a post-development integrity commitment, not retrospective preregistration.

Source contracts and the ten layers

SourceRuntime.term_contracts() builds the registry from the pinned Hebrew and Greek editions. The original source bytes and numbering conventions remain authoritative. Each exact lexical identifier has its own branch; missing compound anchors remain explicit. Source order does not establish historical utterance order.

LayerExecutable responsibility or review question
Whole and SoulBind purpose, target, boundary and recipient.
Word and KnowledgeRetain claims, source references, uncertainty and counterevidence.
SpiritRetain attributed direction and manner criteria; require contextual critique.

UnderstandingMatch the operation to the structured state change.

The source-inquiry contracts expose questions and gaps. They do not authorize an unimplemented effect merely because a term has a biblical anchor. Layer allocations reserve review-planning units; they are not measured GPU, CPU or human-work consumption.

Use the individual expression path

SourceRuntime.begin_expression_cycle(path, covenant) opens the source-verified expression executor. Admit a target with the existing identity, kind, recipient, version, content, status and source references plus a semantic state. Old prose can be explicitly imported with semantic_review.initial_state; it enters as unreviewed.

An envelope uses CE-EXPRESSION-OPERATIONS-1.256. It retains the earlier disposition and six grouped layer strings for compatibility and adds layer_mix and semantic_plan. layer_mix binds the ten-layer account to the operation contract. semantic_plan contains permitted steps and attributed critiques. The example packet builder supplies authored fixtures only.

OperationPermitted change
QUALIFYMake selected unsupported claims unresolved; preserve supported facts and evidence.
WITHDRAWDeactivate assertions and retain their history.
PAUSESuspend eligibility of an internal process and record a resume condition.
CLARIFYExpand the structured presentation without adding a new fact.
PROPOSE_REPAIRRetain a proposed step, prerequisites, preservation needs and outcome check.

Call ingest, calculate and execute_expression with current snapshot and host checks. The executor recomputes the full assessment and semantic result before committing. A high score cannot override a mismatch. The candidate content must exactly equal the controlled rendering.

Construct and execute a mixed behavior

SelfBuilder.generate(target, request, evidence) accepts declared goals, a question, a review endpoint and tick, ten layer weights and a finite search budget. Goals include QUALIFIED, WITHDRAWN, PAUSED, DETAILED and QUESTION_RETAINED. Conflicting goals require separate alternatives. The builder returns a BehaviorManifest and a construction record.

BehaviorCompiler.compile(manifest, target, evidence) validates source contracts, permissions, node identities, backward dependencies, costs and state transitions. The current implementation supports at most sixteen serial nodes. Source inquiry comes first, preservation second and a future review last. Arbitrary handlers, code strings and external capabilities are rejected.

SourceRuntime.begin_behavior_cycle(path, covenant) opens the mixed executor. Register one EXPRESSION action containing behavior_manifest, target_ref, target_digest and semantic_critiques. Its cost equals the graph node count. The candidate contains the compiled prose. Use the existing seven-score vector and current covenant checks, then call calculate followed by execute.

The complete graph commits once, preserving before and after state, node results, source inquiry, layer accounts, critiques and profile scores. An exact retry returns the same receipt. A changed snapshot, target, review or permission requires reassessment. Questions and scheduled review are retained state; neither constitutes an observed benefit.

Semantic review and profile participation

semantic_review.critique_prompt prepares a transport-neutral review request. The application supplies the actual evaluator identity, model, prompt version and origin. Reviewers assess contextual relevance, meaning preservation, dignity and scope of support. Required results are PASS, FAIL or UNRESOLVED; material disagreement remains visible.

The review binding includes the exact target, steps, evidence, proposed content, context and evaluator configuration. A stale critique cannot authorize changed prose. Quoted and refuted wording remains data. Deterministic transformations prevent some semantic contradictions, while evidence relevance and unrestricted language truth still require substantive review.

Keep profile scores as seven comma-separated integers in this order: Elijah, Moses, David, Daniel, Job, Noah, Abraham. Optional participation is a matching comma-separated ASSESS or ABSTAIN vector. Each abstention needs a reason, an unchanged baseline prediction and zero confidence. It earns no benefit contribution and does not waive mandatory host checks or profile floors.

A trusted host supplies evidence and authority assertions. Retrieved text and model output do not grant capabilities. This release does not authenticate an external service, isolate a compromised host or make multiple calls to one model independent witnesses. The current demonstrations identify their critique origin as AUTHORED_TEST.

Evaluate promote and recover

Create FrozenEvaluator with held-out structured tasks before exposing any comparison result to the generator. Commit the primary metric, practical gain, critical-failure allowance, nominal significance threshold and attempt limit. The default allows one attempt and requires no candidate critical failures or paired losses.

DevelopmentCycle.evaluate_and_promote retains a candidate attempt before evaluation, computes the comparison through the fixed evaluator and selects a passing successor automatically. It does not accept candidate-supplied scores. Failed evaluation, a tie or insufficient gain remains recorded. Reopening the store preserves the attempt budget.

rollback records a reason and restores the retained predecessor. It is an explicit host operation in this reference; autonomous live regression detection remains future work. Evaluation and rollback commit code and policy identities. Hashes support integrity checking within the trusted host, not independent authentication or a trusted timestamp.

The included 12-case comparison shows that the generated successor completes all required structured task bundles while the limited incumbent completes none. Those bundles require qualification, detailed presentation and a retained question. The result supports that narrow functional comparison. It is not a measured speedup, independent scientific discovery, clinical outcome or comparison against ordinary AI.

Migration and remaining integration

The 2.16 expression policy is retained in history. A 2.17 runtime will not reopen an earlier session under a different code manifest. Preserve the old store, export its records with provenance, explicitly import them into a new session and reassess before mutation. Importing a parser-compatible record does not retroactively validate its meaning.

Current schemas cover the expression envelope, layer mix, semantic plan, semantic state and behavior manifest. Runtime checks additionally enforce source identity, graph ordering, allowed parameters, evidence preservation, byte limits and review binding. Schema validation alone does not authorize execution.

Broader contextual work: complete the 88 source-inquiry effect specifications and resolve compound or sense-specific anchors where supported.

Live integration: connect a real semantic evaluator, Gemma transport, Unity receipts and durable wall-clock scheduling.

Operational assurance: add production authentication, privilege separation, concurrency and external-effect reconciliation.

Measured improvement: evaluate independent tasks, calibrated predictions, real recipient outcomes and comparison workflows.

The active release implements layered contracts, constrained semantic execution, mixed composition and bounded development. General autonomous code synthesis and real-world outcome adaptation remain separate capabilities.
