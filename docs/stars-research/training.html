03 / ChristEye technical documentation

A program that can fail honestly.

A replicable development plan for cultured-network research: identify the interface, pre-register the task, teach under controlled feedback, test retention after delay, and separate every claimed contribution.

RESEARCH DESIGN / v0.4NONCLINICALUPDATED 13 NOV 2026
Execute the study: view the 18-trial implementation plan or record run-level results in the working notebook.

The closed-loop research sequence

Encode→Deliver→Record→Decode→Score→Feedback→Rest & test

The task environment exposes a defined codebook to an independent cartridge, records neural responses, applies a frozen readout for scoring, then supplies outcome-contingent feedback only in training blocks. In evaluation, labels and feedback are withheld from the learner and its observer. Measured delivery is always logged separately from requested stimulation.

Freeze the task and codebook

Prespecify stimulus family, context, timing, outcome class and a decoder. Build negative controls that have equal sensory exposure without task-contingent feedback.

Prove interface competence

Before claiming a learned response, show distinguishable evoked patterns, valid recording regions, artifact recovery, synchronized timestamps and independently assessed viability.

Train within qualified conditions

Encode the cue through approved hardware profiles. Record a response window, decode after artifact masking, score against protected labels and return qualified feedback only after response closure.

Stop teaching; measure retention

Freeze the decoder and test at declared delays without contingent feedback. Report learning and loss relative to chance as separate outcomes, with complete invalid and late denominators.

Add components with matched controls

Train the observer independently, compare joined versus isolated service, include simple digital baselines and disconnect the teacher for recipient-only assessment.

A reference X / Y / HOLD task

The physical design proposes a controlled synthetic context problem with three outputs X, Y, HOLD rather than claiming any native semantic competence. It is designed to test context sensitivity, retention and task interference, not to solve a real medical decision.

Each episode declares a valid context signal, a sequence or cue relation, one correct output and an allowed response window. The task generator must prevent leakage through file names, channel order, stimulus energy, duration or service timing. Use counterbalanced positions and contexts and generate holdouts independently. The exact cue mapping belongs to the versioned task contract, not a floating web-site “recipe.”

Functional outcome definition

Macro-averaged recall across X, Y and HOLD, report per context and sequence cell. Freeze the decision window, electrode region assignment and decoder digest before a sealed confirmation cohort.

Training observers and support communities

O learns to discriminate a small set of independently defined operating states from a permitted portion of C telemetry: e.g., nominal response, interface anomaly, response access problem or unknown state. The observer should be tested on episodes and entire preparations it did not see in training. Learning must be separated from an instrument threshold or a deterministic cue leak.

O1 detection and O2 early warning are different claims: a model that recognizes an error after it occurs is not a predictor. A useful warning must use pre-outcome features, provide lead time and beat a matched digital baseline. S receives state summaries and may propose only NO CHANGE, REQUEST REVIEW, DEFER TASK or TRY APPROVED ALTERNATE ROUTE in its earliest qualification. It never gains unrestricted control of media or stimulation limits.

G1–G6 evidence gates

The physical design and Theory Set both demand gated progression but number gates differently. The following uses the physical design v0.4 G1–G6; it records the interface, joining, contribution and independence sequence. In the Theory Set, G4 is named learning, G5 bridge and G6 support. Preserve the document/version mapping rather than assuming the two numbering schemes are identical.

G2 · MaturationIs the receiving community viable and stable?Cell composition, synaptic organization and functional development record
G3 · InterfaceCan the system accurately read and drive responses?Artifact, SNR, latency, repeatability and stimulation inhibition tests

Gated qualification is not a universal safety certification. The laboratory and institution must approve any living-tissue work, procurement limits and the precise SOP. A gate can fail, close or be revised prospectively; no failure is converted into a pass by changing its name.

Comparison design and statistical discipline

The biological preparation—not an electrode, neuron, burst, video frame or trial—is the independent experimental unit. Block by source batch and release conditions. Adjacent windows from a single preparation must not be randomly split between training and testing; use independent preparations, forward-time evaluation and a sealed confirmation cohort. Predeclare exclusions, stopping criteria, missingness and multiplicity adjustments.

The physical design includes an illustrative two-arm calculation using assumed preparation-level SD 0.08 and difference 0.10: approximately 11 analyzable units per arm, or 14 enrolled with 20% attrition. The Theory Set shows a generic standardized-effect example n ≈ 15.7/d² per arm. These are different assumptions, not competing observations; neither replaces a protocol-specific simulation.

Controller / evaluator pseudocode

// Conceptual host loop — not live stimulation software.
for (const trial of frozenSchedule) {
  assert(currentReleaseGate.permits(trial.mode));
  const input = encode(trial.cue, codebookVersion);
  const decision = independentLimitController.check(input, liveSensors);
  if (!decision.permitted) { logVeto(decision); continue; }
  const measured = readQualifiedResponse(input, timingWindow);
  const prediction = frozenDecoder(measured.validFeatures);
  const outcome = evaluator.scoreAfterResponse(prediction, trial.protectedTarget);
  if (trial.mode === 'TRAINING') {
    deliverQualifiedFeedback(outcome); // permitted profile only
  }
  appendImmutableRecord({ trial, decision, measured, prediction, outcome });
}
// EVALUATION mode never returns teaching feedback.

Controller and failure modes

Independent operating states include RECEIVING, MATURING, READY, TRAINING, REST, EVALUATION, SENSOR STALE, STIMULATION FAULT, FLUID FAULT, HOST LOSS and RETIREMENT. Each has a declared permit policy and recovery record. No “learning” event can bypass stale-sensor inhibition, qualified electrical and fluid limits or a watchdog failure.
